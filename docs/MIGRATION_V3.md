# Migrating from ARC v2.x to v3.0

ARC v3 replaces provider-specific background execution with the Agent Skills format and the host AI agent's native execution/delegation capabilities.

## What changed

- Skills live canonically under `.agents/skills/<skill-name>/SKILL.md`.
- Workflow prompts and role definitions are now portable Skills rather than slash-command files that depend on an MCP-triggered agent runtime.
- The host agent executes the workflow. Native subagents are used when supported; sequential execution is the fallback.
- Gemini CLI authentication, model selection, background worker execution, and Google AI SDK dependencies are removed from core setup.
- Python validation, mapping, dashboard, and project-state tooling remain available.
- MCP is optional and exposes deterministic workspace utilities only. It does not spawn agents or execute arbitrary shell commands.

## Upgrade steps

1. Back up or commit your project before migrating.
2. Pull ARC v3 and run `python3 setup_arc.py`.
3. Add `.agents/skills/` to your agent environment's Skills discovery path. Some clients discover it automatically; others require a client-specific directory or configuration.
4. Start with `arc-map` for existing repositories, or `arc-resume` for an existing ARC project.
5. Review existing `.arc/` files. The installer does not overwrite user project state.
6. Use `arc-discuss` and `arc-plan`, approve the plan, then `arc-execute` and `arc-verify`.

## Compatibility

Existing `.arc/` project artifacts are preserved. The old `.agent/workflows/`, role prompt, and legacy skill locations are retained as migration pointers. The old `background_agent.py` entry point exits with migration guidance and does not launch a provider runtime.

## Host-specific discovery

Skills discovery varies by client and version. Keep `.agents/skills/` canonical and use the client's documented Skills discovery path or a symlink/copy generated by the user. Do not assume MCP is required for Skills discovery.
